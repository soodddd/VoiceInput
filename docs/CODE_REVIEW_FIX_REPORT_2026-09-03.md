## 项目结论

这是一个 Windows 本地语音输入工具：React/Tauri 负责悬浮窗、全局快捷键、
麦克风录制和向原窗口输入文字；Python/FastAPI/Qwen3-ASR 负责本机 GPU
推理。语音只允许发往 Rust 启动的随机 127.0.0.1 端口。

## 已修复

- 自动输入改为 Windows Unicode SendInput，不再清空或延迟恢复剪贴板；
  点击悬浮窗录音时会记住并返回之前的外部输入窗口。
- 识别成功但自动输入失败时，结果仍显示并可复制，不再因粘贴失败丢字。
- React 录音操作增加同步互斥状态；按钮改成明确的点击开始/点击停止，
  快捷键仍保持按下开始、松开停止，VAD/超时/松键不会重复停止。
- 录音器只在 WASAPI 流成功启动后进入录音态；优先按稳定设备名选择；
  使用完整原生设备配置并由后端重采样；缓冲区受最大时长硬限制。
- VAD 使用配置中的 dB 阈值；归一化、裁剪静音、最大录音时长等设置
  已真正传入后端，不再是无效开关。
- 音频先检测/裁剪静音再限幅归一化，避免把底噪放大成语音；
  长音频强制满足分块上限，重叠区域识别文本会去重。
- 模型加载只接受完整本地目录，不再隐式访问模型仓库；下载路径确定化，
  本地模型路径可通过目录选择器传入并持久发现。
- 模型目录必须同时具有 config.json 和权重文件；已修复残缺目录被误判
  的实现错误并加入回归测试。
- 下载状态协议统一；取消后必须等待实际下载线程退出，期间不能启动
  第二个下载线程。
- 模型加载、卸载、策略变更和推理串行化；阻塞工作移出 FastAPI 事件循环；
  上传限制为 64 MiB，推理请求串行，转录正文不写日志。
- 修复空闲释放线程调用自身 join 的问题；memory 策略在成功或失败后
  都会执行释放检查。
- 后端使用随机回环端口和每次运行新 token；地址/token 不持久化且不暴露
  给 WebView；移除 shell 执行权限和启动时 GitHub 联网。
- 后端路径只从受信任的应用目录查找，不再回退 PATH，也不再使用旧的
  2.7 GB 单文件 sidecar；进程退出、失去健康响应和应用退出均有明确处理。
- 快捷键改为单一永久监听线程加热更新配置，避免每次保存设置泄漏线程；
  前后端支持键集合一致，并拒绝无修饰键或两个相同快捷键。
- 配置支持缺字段迁移、范围校验、损坏文件备份和保存前备份；模型策略
  先由后端接受再落盘，取消设置不会提前卸载模型。
- 模型状态、下载状态、模型路径和转录返回结构已统一；状态轮询不会重叠，
  异步事件监听卸载时不会遗留。
- 发布方式改为 PyInstaller onedir + 自定义 ZIP；发布脚本要求 _internal，
  生成 SHA-256 清单，并从全新解压目录启动后端执行 /health 冒烟测试。

## 0.1.4 补充修复与验证

- 录音器把 `cpal::Stream` 的创建、持有和释放放在同一个专用线程，停止时先通知线程退出并等待回收。
- 实时回调只处理采样和原子 RMS 快照；`audio-level` 改由 50 ms 采样线程推送，避免 WebView 通信阻塞音频回调。
- `stream.play()` 成功后才重置 VAD 起始时间；停止日志补充总 RMS 与峰值，VAD 日志补充当前/最高 RMS。
- 新增 `audio_hardware_probe`，已验证蓝牙输出到麦克风的实际能量约为 -20 dB RMS，静音基线约为 -104 dB RMS。
- 后端测试已增加到 8 项；0.1.4 版本配置、sidecar 日志、双语 README 和发布文档已同步。
- 用户现场已完成一次识别和目标窗口输入；可重复的命令与边界见 `VALIDATION_v0.1.4-preview.*.md`。

## 仍需真实设备验收

构建和本机软件冒烟已经完成；尚未把“服务健康”冒充成完整识别验收。正式现场
验收仍需在目标机器上用真实 NVIDIA GPU、真实麦克风和实际模型执行：

1. 选择/下载完整模型并完成模型加载。
2. 点击录音、Alt+V 按住/松开、VAD、最大时长、中文/英文识别。
3. 验证目标窗口输入、无目标窗口提示、管理员权限窗口失败提示。
4. 连续使用和显存释放/重新加载。

在上述设备验收完成前，结论是源码、桌面 release、后端打包和本机服务冒烟通过，
不是完整现场语音识别 E2E 已验收。
